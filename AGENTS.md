# AGENTS.md

Guide for coding agents editing this repo. Runtime behavior lives in code, `resources/` and `src/doctours_reply/policies/`; this file only guides edits. CI is the enforcer.

## Layout

- `src/doctours_reply/contract/`: the `Reply` and input contract (packet L37-82).
- `src/doctours_reply/tools/`: faithful port of the 14 packet tools, driven by fixture data; `registry.py` holds argument models, read/write kinds and `xTool` aliases.
- `src/doctours_reply/runtime/`: `refs.py` resolves `fixture_id` and `policy_set_id` from `resources/`, verifying hashes. The shared executor, evidence, grounding, validators, redaction, outcome slot, pure finalizer and the per-item pipeline also live here. So does S1 (decision record 0002): `modular.py` (the flow), `controller.py`, `decision.py`, `controller_io.py` (step serialization), `writer.py`, `policy_loader.py` and `model_calls.py`.
- `src/doctours_reply/policies/`: versioned policy modules with TOML front matter, in `core/`, `context/`, `skills/` and `writer/` (decision record 0004). Edit them with `.agents/skills/policy-change/SKILL.md`.
- `schemas/`: snapshots of the `Reply` schema and S1's route and decide schemas; changes are deliberate.
- `src/doctours_reply/baseline/`: S0, the monolithic baseline (decision record 0003). `models/`: the OpenAI-compatible client and the scripted test client. `trace/`: trace schema, redaction and sink. `cli.py`: `doctours-reply run`.
- `src/doctours_reply/evaluation/`: `doctours-reply eval`, scorer, report and held-out schedule. Runtime modules never import it; `cli.py` dispatches to it lazily.
- `src/doctours_reply/prompts/legacy/`: verbatim packet templates.
- `resources/`: runtime inputs only (fixtures, policy sets, hashed manifests). Never labels or answers.
- `eval/`: evaluation cases, labels and answers. The runtime never reads it. `eval/heldout/` is frozen by hash and runs only with `--log-entry`.
- `docs/assignment/`: the verbatim packet, read by tests only. `docs/spec/`: traceability and the ambiguity ledger. `docs/decisions/`: decision records. `docs/phase-reports/`: verification records.
- `scripts/`: `extract_packet.py`, `gen_tool_goldens.mjs` (Node 22.6+, development only), `audit_submission.py` (stdlib only).
- `tests/`: `unit/` (scripted model responses, no network), `conformance/` (TypeScript reference and goldens), `guards/`, `live/` (opt-in with `RUN_LIVE=1` and `MODEL_*`).

## Checks

CI runs exactly these, in order:

```sh
uv sync --locked
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest -m "not live"
uv run doctours-reply eval --dry-run --suite all
uv run python scripts/audit_submission.py --history
```

Development-only regeneration checks (their results are also asserted by tests):

```sh
uv run python scripts/extract_packet.py --check
node --experimental-strip-types scripts/gen_tool_goldens.mjs --check
```

## Non-negotiables

- The `Reply` contract is fixed: no new fields, and schema snapshot changes are deliberate.
- Tools match the TypeScript goldens. Fix the port; never hand-edit a golden.
- Packet-derived files are regenerated by the extractor, never edited by hand.
- The runtime reads `resources/`, never `eval/` or `docs/`. `resources/` holds no labels or expected answers.
- Never special-case the official messages or put expected outputs where the runtime can see them.
- Never edit a frozen held-out set or run it outside its schedule row. Never mark a live check passed without running it.
- Nothing private: no plans, weights, credentials, generation or training material, or references to other repositories.

## Phase report template

`docs/phase-reports/phase-N.md`:

1. Scope delivered.
2. Checks run: command, actual output, result.
3. Checks not run, and why.
4. CI: `gh run list --branch main --limit 1 --json headSha,conclusion` against `git rev-parse HEAD`.
5. Deviations and decisions.
6. Open questions and blockers.
